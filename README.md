# agent-evals-and-harness

**Question.** How should an agent be evaluated so its numbers can be
trusted: trajectory logs, a held-out set kept apart, pass@k with
variance, one-at-a-time ablations, a failure taxonomy from real runs
and a contamination hygiene report?

**Headline.** On a deterministic toy agent (not an LLM), removing the
planner cut mean attempt success from 0.98 to 0.4411 over 36 tasks
(5 master seeds x 5 attempts, seed standard deviation 0.0075 and
0.0044; no interval over tasks), and all 1,285 failed attempts of
4,500 fall into one taxonomy class each. The effects are fixed by how
the toy is built, so this shows the harness works, not how real agents
behave.

**Field.** ML and AI research. **Job family.** AI evaluation and
agent engineering.

**Verdict.** Functional, not pre-registered. Tests pass in CI on
Python 3.11 and 3.12, each result file is regenerated by one command
and CI fails if it differs from the committed copy, and an independent
JavaScript replay reproduces every recorded cell. No plan was locked
before the runs; the confirmatory re-run on a real agent is drafted in
PROPOSAL.md and is not locked.

Live dashboard: https://jesunahmadushno.github.io/agent-evals-and-harness/

Boundary: P06 (rag-eval-harness) judges a RAG system; P27 evaluates an
agent's trajectory of tool calls.

## Reproduce

```text
python level-1-learn/run_learn.py
python level-2-build/run_build.py
python level-3-deep/run_deep.py
python level-3-deep/hygiene_sensitivity.py
git diff --exit-code -- level-1-learn/results_learn.json level-2-build/results_build.json level-3-deep/results_deep.json level-3-deep/results_hygiene_sensitivity.json
python -m unittest discover -s tests -p "test_*.py" -v
node site/src/engine.check.mjs
```

Python 3.11 or 3.12, standard library only, no API calls, no GPU; the
whole run takes seconds on a CPU. The runners are deterministic: a
clean `git diff` means the committed results were reproduced.

## Layout

| Path | Role in the standard | What it holds |
| --- | --- | --- |
| PROPOSAL.md | Proposal (not locked) | Original scope, proposed novelty, Deep spec, draft confirmatory re-run |
| REPORT.md | Report | Results, observations, background, the three runs, review, limits, future work |
| level-1-learn/ | Code, evidence, results | Toy agent and evaluator (agent_eval.py, run_learn.py), tasks_learn.json, results_learn.json |
| level-2-build/ | Code, evidence, results | Eval suite and ablation harness (eval_suite.py, run_build.py), tasks_dev.json, tasks_heldout.json (SHA-256 recorded), results_build.json |
| level-3-deep/ | Code, results | Taxonomy and hygiene (deep_analysis.py, run_deep.py, hygiene_sensitivity.py), results_deep.json, results_hygiene_sensitivity.json |
| tests/ | Tests | Unit tests per level, the threshold sweep, and the layout test |
| site/ | Dashboard | JavaScript replay of the harness, checked against the results at build time |
| docs/decisions/ | Decisions | 0001: why code and results stay in the level folders |
| fanout/ | Outreach drafts | Blog, tutorial, release notes and other drafts (nothing posted), PUBLICITY.md log |
| CHANGELOG.md, CITATION.cff, SECURITY.md, LICENSE | Release files | |

No experiments/ or results/ folder: the evidence inputs are the
committed task files and the results are regenerated next to the code
that writes them (docs/decisions/0001).
